# 验证报告

发布日期：2026-11-02（Asia/Shanghai）。

## 独立行为审查

一位未参与实现的审查agent只读取skill与相关文档，模拟三个请求，不调用生图或实际编辑。

|情境|应得决策|审查结论|
|---|---|---|
|仅有参考图生图能力；两人东京8秒片|两套身份资产、场景、提示和明确时间配方；缺合成工具不伪造MP4，也不声称动态验证|规则能支持|
|只有半身图；自然步行且品牌不变|不能靠浏览器凭空产生腿；复用品牌像素，补全身素材或明确生成路线后检验|规则能支持|
|只要6张咖啡贴纸|交付6张独立静态素材和清单；不扩张到人物/分镜/视频|规则能支持|

没有发现核心决策P0/P1。审查时指出尚未落盘的渲染说明、许可和本报告缺失，发布前已补齐；将“浏览器/Node”改为明确的Node + Chromium/Puppeteer + FFmpeg，英文依赖补上Python3。

这是文档行为演练，不是对所有模型/agent的实机认证。生成器是否保持身份、输出alpha或正确交换腿仍需实际检查。

## 可执行路径与包检查

- 无动画框架Canvas模板：实际通过本地Chromium/Puppeteer与FFmpeg导出2秒测试，270×480，H.264 + AAC。完整9秒测试也已通过，并检查8张编码后关键帧覆盖动作、两次转场和结尾。测试环境Node25.7.0、Puppeteer-core25.5.0、本机Chromium；公开依赖锁定Puppeteer25.5.0，要求Node22.12+。GIF转换和抽帧脚本均实际运行成功。
- 每份归档原MP4按SHA-256核对，与已交付文件一致。
- 11个GIF与对应MP4时长逐项核对，允许不超过0.2秒的采样/容器差；GIF为12fps、270px宽、无声。
- 75张图片的文件与SHA-256逐项检查；参考输入另存6张。
- 检查主说明、skill、引用文档链接，以及历史HTML引用的asset文件、便携示例的图片/音频路径。
- 扫描个人绝对路径、常见凭证前缀及100MiB以上文件；不发布缓存或系统字体。
- `quick_validate.py`检查skill结构；`scripts/verify_package.py`可重复运行以上静态与媒体检查。

具体自动检查结果见 [package-check.json](package-check.json)。

## 未声称的验证

未对任意生图服务做批量兼容认证；未人工试听所有音轨；未承诺跨平台字体像素一致。旧工程包含历史缺陷并已标注，不能把“文件完整”理解为所有旧版动作都正确。独立模板只负责明确的2D拼贴，不自动修复图片中的解剖错误。

## 原参考补充验证

新增用户提供的完整原片（独立reference角色），核对SHA-256与原文件一致。另生成216px、8fps、完整时长GIF。识别为香港主题的5个主体场景及2个收尾段，保存机器可读时间段；没有将未标明的街市/咖啡/夜景猜成具体区域。现在共有11个制作输出＋1个原参考，各有MP4与GIF。
